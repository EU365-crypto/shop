Subcategories use the existing SQLite catalog snapshots. Each category optionally stores an ordered `subcategories` array of `{id,en,zh,vi}` objects; each product optionally stores `subcategoryId`. Array order is display order, and nesting records the parent relationship. Existing snapshots without these optional properties remain valid. No schema alteration, database reset, or product migration is required.

The existing Save Draft transaction persists category lists, product assignments, private history and catalog revision together. Publish atomically replaces the public snapshot. Customers read only the published snapshot. Existing admin authorization, CSRF middleware and revision conflict checks protect these requests.

Admin category sections include Manage Subcategories. Its Add/Save controls update the local working state; use the toolbar Save and Publish controls to persist and publish. Removing a subcategory requires confirmation with the affected product count and clears assignments without deleting products. Changing a product's parent clears its subcategory. Discard restores the saved category lists and product assignments together.

Customer dropdowns filter by stable parent and subcategory IDs. Only the selected row and its visual repetitions rebuild. Other filters are retained across catalog refreshes when their IDs still exist. See All carries both IDs in the URL. Visual loop copies never enter SQLite or cart records.

The customer default option is simply All. Its logical cycles sample at most two distinct products per subcategory and two unassigned products. Shuffled per-group bags rotate choices fairly; the merged ordering separates groups when possible, including cycle boundaries. Upcoming cycles are appended ahead of the viewport and completed cycles retired offscreen with a compensating scroll offset. Specific-subcategory filters continue showing all products in that subcategory. Cart interactions and pauses preserve prepared sequences.

Restart Node.js after deploying backend changes, then refresh browser pages. Run `npm.cmd test` on Windows. Tests cover snapshot persistence, privacy, invalid relationships, rename/order/removal, dirty/discard behavior, filter isolation, loop inputs, cart isolation and existing authentication. Real-device Safari, screen-reader and responsive visual checks still require browser verification.
